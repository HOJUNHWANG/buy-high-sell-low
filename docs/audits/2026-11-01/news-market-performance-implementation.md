**뉴스 요약·시장 데이터 로딩 개선 — 2026-11-01**

이전 [진단](news-summary-and-loading-review.md)에서 확인한 원인을 수정했다. 기사 원문 발췌와 검증된 AI 문장 선택은 계속 구별하며, 거래·청산 가격 검증에는 화면 표시용 캐시를 사용하지 않는다.

- Fool 공개 본문과 Cointelegraph `.ct-prose` 추출을 지원한다. HTTPS·허용 도메인·공인 DNS·리다이렉트 검증 및 크기/시간 제한은 유지한다.
- 짧은 설명도 완결 문장·제목 반복·잘린 문장·홍보 문구를 검증해 발췌로 제공한다. AI는 원문 문장 ID를 선택하고 서버가 해당 문장을 복원한다. 주체·금액·부정 표현·미국 등의 약어를 보존하는 회귀 테스트를 추가했다.
- 실제 모델 호출만 예산에 포함하고 정상 수집 실행에서 재처리 예산을 남겨 둔다. 원문 오류·HTTP 상태·모델 오류·예산 미배정을 구분한다. 429는 제공처 대기와 Retry-After를 적용한다.
- 서비스 역할만 접근하는 재처리 큐를 추가했다. 최근 72시간, 최대 4회 재시도, 실행당 120건 이하, 전체 모델 40회 제한이다. 확보한 본문을 재사용하며 검증된 요약을 실패 결과로 덮어쓰지 않는다. v2 원본 기사와 비공개 근거는 실제 복구 시 트랜잭션 안에서 보관한다.
- URL 제공처 도메인으로 피드 다양성을 계산하고 명백한 패키지·할인·스포츠 검색 노이즈를 신규 수집에서 제외한다.
- 공용 시장 스냅샷·뉴스·종목별 차트 이력은 쿠키 없는 익명 DB 클라이언트로 조회해 60초 공유 캐시에 저장한다. 스크리너 비교 이력과 브리프는 300초다. 실패 결과는 정상 빈 데이터로 캐시하지 않는다. 실제 시세 수집 시각과 공급자 세션 날짜를 보존한다.
- 홈·스크리너·종목·뉴스 위젯은 데이터를 재사용한다. 종목 메타데이터 조회가 전체 차트와 뉴스를 기다리지 않도록 분리했다. 스크리너의 중복 시세 객체 전송을 제거하고 많은 종목 링크는 접근·포커스 때 프리페치한다.
- 사용자 인증은 기존 getUser 검증을 유지한다. 서버 사용자 조회는 요청 안에서 재사용하고 브라우저의 동시 검증을 합친다. 프로필·열람 기록은 사용자별로 확인하며 두 조회를 병렬 실행한다. 사용자 데이터와 권한 판정은 공용 캐시에 저장하지 않는다.
- 모의투자는 대시보드 API 하나로 조회한다. 인증된 사용자만 대상으로 하며 청산 후 계좌를 읽는 순서를 유지한다. 챌린지 오류가 계좌 화면까지 막지 않도록 했다. 기존 개별 API도 같은 내부 로직을 사용한다.

마이그레이션 `20261101161717_news_retries_and_market_loading`을 운영에 적용했다. 뉴스 발행일·ID 및 시장 일별 이력 날짜 인덱스를 추가했고 기존 최근 기사 529건을 큐에 넣었다. 사용자 금융 테이블의 스키마나 잔액은 이 마이그레이션에서 변경하지 않는다.

최신 뉴스 240건의 운영 SQL 실행 시간은 인덱스 전 927.892 / 1218.855 / 204.634 / 132.686ms에서 적용 후 163.313 / 1.423 / 0.486ms였다. 계획은 `Seq Scan + Sort`에서 `news_articles_published_id`의 `Index Scan`으로 바뀌었고 버퍼 접근은 1424개에서 238개로 감소했다. 측정 횟수가 적고 서버 자원 상태가 달라 개선 배수를 일반화하지 않는다.

로컬 프로덕션 빌드의 로그인 검증은 홈 1.088 / 0.689초, 뉴스 0.411 / 0.382초, AAPL 1.229 / 0.359초, 모의투자 2.176 / 1.654초였다. 8회 모두 HTTP 200, 브라우저 오류 0건, 임시 사용자 정리 완료다. 로컬 수치는 운영 배포 후 실측으로 별도 확인해야 한다.

검증: TypeScript/TSX 196개, Python 173+15개, 뉴스 큐 PostgreSQL 권한·재시도·원본 보관·롤백·검증 결과 보존, 기존 금융 SQL 현금 보존·동시성·신선도 테스트, 타입 검사·린트·프로덕션 빌드 통과.

기존 시스템 볼륨 스왑 I/O는 앱 변경만으로 해소됐다고 판단하지 않는다. 배포 후 로딩 편차와 함께 계속 확인할 항목이며 서버 재시작이나 요금제 변경은 수행하지 않았다.

**운영 반영과 최종 결과**

[PR 13](https://github.com/HOJUNHWANG/buy-high-sell-low/pull/13), [PR 14](https://github.com/HOJUNHWANG/buy-high-sell-low/pull/14), [PR 15](https://github.com/HOJUNHWANG/buy-high-sell-low/pull/15)을 main에 반영했고 런타임 커밋 `80ffa428c3eb85986b248756f8c5fbd9a80dd299`의 Vercel 운영 배포를 확인했다. 이후 보강한 기준은 다음과 같다.

- 원문 그대로인 문장도 정보량이 부족할 수 있어, 추상적인 전환 문장·수사적 문구를 후보에서 제외하고 제목 맥락 또는 금융 사실을 요구한다. 검토한 기존 11건은 기사·비공개 근거를 별도 보관한 뒤 유효한 발췌로 교체하거나 요약 없음으로 정정했다.
- NewsAPI 검색을 제목·설명으로 제한해 본문 하단의 회사 이름 때문에 무관한 기사가 유입되는 경로를 줄였다. 신규 수집 전에 명백한 스포츠·할인·개인 상담 잡음을 제외하되 거시경제와 실제 스포츠 기업의 실적·지분·중계 사업 뉴스는 유지한다. [검색 옵션 근거](https://newsapi.org/docs/endpoints/everything)
- 공용 시장 뉴스·신호는 시장 관련성 기준을 적용한다. 원본 기사 삭제는 하지 않았다. 아래 복구 지표는 필터 적용 여부와 관계없이 기존 210개 전체를 계속 센다.

요약 없음은 65건 감소했다. 모든 기사를 복구할 수 있는 것은 아니며, 접근 제한·원문 부족은 출처 링크와 함께 표시한다. 일시 장애·모델 예산 대기는 기존 실행 주기에서 한도 내 재시도한다. 마지막 확인의 큐는 290건(실행 가능 160건)이며 신규 수집과 재시도로 계속 변한다.

최종 게스트는 홈 0.683~0.846초, 뉴스 0.559~0.640초, 스크리너 0.565~0.688초, AAPL 0.515~0.599초였다. 브리프는 첫 1.481초·반복 0.490/0.570초로 초기 지연이 남는다. 한 위치의 소수 표본이며 수집 작업·QA가 실행되던 구간이므로 사용자 전체의 p95나 보장 지연을 뜻하지 않는다.

운영 데스크톱·모바일에서 주식/ETF/크립토 실제 시세와 AAPL/BTC 1년 차트 표시, 가로 넘침 없음, 브라우저 오류 없음 등 10개 표시 검증을 통과했다. 별도 서버 계측에서 `/stocks`와 `/stock/AAPL`의 반복 렌더는 추가 공용 DB 조회 0회였다. 원시 기사·사용자 데이터·키를 제외한 [측정 근거](news-market-after.json)를 보관했다.

마지막 약 251초 구간에도 시스템 볼륨 I/O busy 약 52.8%, 데이터 볼륨 약 0.2%, 스왑 입출력 약 1,230/1,201페이지/초가 관찰됐다. 중간 Metrics API 요청 한 번은 시간 초과됐고 다음 요청은 성공했다. 시스템 스왑 문제와 하루 DISK IO 경고가 해결됐다고 보고하지 않는다. 앱 조회 부하는 줄었지만 서버 자원에 의한 지연 변동은 별도 점검 대상이다.

운영 금융 E2E 9개 항목도 통과했다. 동시 매수·멱등 요청·롱/숏 분리·직접 금융 쓰기 차단·원장과 잔액 일치·보상 중복 방지·QA 순위 제외·회원 화면 로딩을 확인했고 테스트 데이터와 Auth 계정을 정리했다. 기존 네트워크 유휴 대기 대신 실제 데이터 표시와 API 응답을 기다리도록 E2E 완료 조건을 수정했다.
