흐름 개선이 필요한 부분:

- 로그인·관심종목·거래 진입 시 원래 종목/화면을 보존하지 않는다. 로그인 성공은 홈(`/`)으로 고정 이동한다. 검증된 내부 `next` 경로로 돌아오게 해야 한다.
- 헤더 검색은 방향키/Enter로 결과를 선택하지 못한다. 실제 테스트에서 입력창에 머물렀고, 결과 버튼을 마우스로 누르면 정상 이동했다. 자동완성의 키보드 선택·Escape 닫기·combobox 상태를 추가하는 편이 좋다.
- 거래 처리 API는 화면에서 검증한 정상 흐름 외에 위의 권한·동시성·롱/숏 구분 문제를 해결해야 한다. 기존 회귀 테스트가 통과한다고 안전한 거래 원장이 보장되지는 않는다.

## 운영·DB 추가 관찰

- 최근 24시간 크립토 수집 144회, 뉴스 48회, 주식 시세 42회, 종가 보충 2회는 모두 성공했다. 최신 교체 버전의 정기 수집도 성공했다.
- 시총 실패 기록과 이전 audit/remediation 기록은 수정 이전 기록을 포함한다. 삭제한 자동 audit가 다시 실행됐다고 판단할 근거는 없다.
- 만료 챌린지와 더미 보유분은 불필요한 은퇴 종목 수집을 유지하는 원인이다. 이 부분은 정리할 여지가 있지만, 이것만으로 기존 DISK IO 경고 전체 원인을 설명할 수는 없다.
- 활성 DB cron 작업은 0개지만 예전 `cron.job_run_details` **181,701행 / 약 51MiB**가 남았다. 기록 범위는 3/26~7/31이다. 현재 실행 부하와 구분하고, 정해진 보존 기간으로 정리할 대상이다.
- 주간 정리는 10/26과 10/19 성공했다. 주간 배치라 30일 보존 자료가 실행 직전 최대 약 37일까지 남는 것은 현재 일정과 일치하며, 그 자체를 오염으로 보지 않았다.
- Supabase 보안 검사에 RLS 꺼진 public 테이블은 없었다. service-only 테이블의 RLS 정책 없음 알림은 접근 차단 의도와 맞는다. 별도 경고는 [공개 스키마의 pg_trgm](https://supabase.com/docs/guides/database/database-linter?lint=0014_extension_in_public), [유출 비밀번호 보호 비활성](https://supabase.com/docs/guides/auth/password-security#password-strength-and-leaked-password-protection)이다.
- 성능 검사에는 [RLS auth 함수의 행별 재평가](https://supabase.com/docs/guides/database/database-linter?lint=0003_auth_rls_initplan) 18건과 미사용 인덱스 정보 3건이 있었다. 사용량과 실행 계획을 확인해 후순위 최적화한다.

## 검증 결과와 후속 순서

현재 코드에서 앱 167개 + Python 154개 = **321개 테스트**, 격리 PostgreSQL 회귀, 타입 검사와 운영 빌드가 통과했다. 별도의 격리 재현은 기존 테스트가 놓친 세 가지 원장 결함을 확인했다.
