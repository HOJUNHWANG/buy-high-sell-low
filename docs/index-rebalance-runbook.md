# 지수 종목 교체 운영 절차

S&P 100 등 구성 종목을 교체할 때 사용하는 실행·검수 기준이다. 이번 실행 기록은 [2026년 9월 교체](sp100-refresh-2026-09.md)를 참고한다. **현재 코드는 검토된 한 번의 교체를 예약하는 구조이며, 새 발표를 자동 수집해 다음 교체까지 등록하지 않는다.** 새로운 발표마다 아래 절차를 수행한다.

## 1. 공식 발표와 전체 구성 확인

- S&P DJI 공식 발표의 발표일, 효력일, 편입·편출 목록과 원문 URL을 기록한다. 보도 날짜와 효력일을 구분한다.
- 날짜가 표시된 전체 구성 자료와 현재 DB를 비교한다. ETF 보유 자료를 보조 자료로 쓸 때 현금·선물·머니마켓은 제외하고 티커 표기를 정규화한다.
- 회사 수와 티커 수를 따로 검증한다. 현재 S&P 100은 Alphabet 두 종류를 포함해 101티커다. 다음 발표의 예상 수는 자료로 재확인한다.
- 거래소·회사명·섹터·아이콘 도메인, 공급자별 티커 매핑, 상장일·분할 등 이력 예외를 확인한다.
- `data/`에 날짜별 구성 스냅샷, `docs/`에 아래 실행 기록을 새 파일로 남긴다. 이전 기록을 덮어쓰지 않는다.

## 2. 교체 설정을 한 번에 수정

| 위치 | 확인·수정 항목 |
| --- | --- |
| `scripts/tickers.py` | 교체 직전 전체 구성, 효력일, 편입·편출 목록, 신규 메타데이터·회사명, 공급자 티커 매핑, 수집 후보와 과거 편출 티커 |
| `get_sp100_tickers()` | 날짜 인수와 실제 시계가 같은 경계를 사용해야 한다. 현재 실제 시계 경계는 별도 UTC 상수이므로 반드시 함께 변경한다. 뉴욕 자정의 UTC 시각은 서머타임에 따라 04:00 또는 05:00이다. |
| `lib/sp100-transition.ts` | 효력 시각, 두 목록, 예정일 표시 문구. 편입 예정은 조회만 먼저 허용하고 신규 매매 자격은 DB 활성 상태로 판단한다. |
| `scripts/sync_sp100.py` | 관리 대상과 신규 메타데이터 생성 로직. 현재 신규 섹터는 Information Technology로 고정되어 있으므로 다른 업종 편입 시 반드시 일반화한다. HON 처리처럼 과거 예외도 재검토한다. |
| `scripts/asset_retention.py` | 새 편출일을 추가한다. **이전 편출 종목의 원래 날짜와 수집 후보를 보존**한다. 현재 목록에서만 날짜를 파생시키면 다음 교체 때 이전 종목이 유실될 수 있다. |
| `.github/workflows/seed-market-history.yml` | 수동 입력 기본값과 push 실행의 기본값 두 곳 모두 새 편입 목록으로 변경한다. |
| `scripts/check_sp100.py`, `tests_py/test_sp100_universe.py` | 새 스냅샷·예상 구성 수·검수 날짜와 전후 차집합을 갱신한다. |
| `tests/sp100-transition.test.ts`, `tests_py/test_sp100_operations.py`, `tests_py/test_asset_retention.py` | 새로운 날짜의 직전·정각·직후, 실패·재시도, 보존 만료 경계를 검증한다. |
| 작업의 전환 점검 자동화 | 기존 자동화를 찾아 일정·대상·정상 상태·완료 조건을 새 교체로 갱신한다. 이전 자동화는 최종 검수 후 일시중지되므로 활성 여부도 확인한다. |

교체가 겹치거나 한 번에 여러 효력일을 예약해야 한다면 단일 예약 상수를 덮어쓰지 말고, 날짜별 교체 이력을 지원하도록 먼저 변경한다. 이전 편출 종목을 다시 편입하는 경우 활성 상태 우선 보호도 검증한다.

## 3. 신규 데이터 준비와 사전 노출

환경은 저장된 `.env.local` 또는 GitHub Secrets를 사용한다. 키를 문서·명령 출력·커밋에 복사하지 않는다. 의존성은 `scripts/requirements.txt`와 npm lockfile을 사용한다.

1. 효력일 전에 `python scripts/sync_sp100.py`로 신규 메타데이터를 비활성 상태로 등록한다. 이 명령은 쓰기를 수행하며 현재 날짜만 사용한다.
2. 신규 티커를 명시해 `python scripts/seed_history.py <NEW1> <NEW2>`와 `python scripts/seed_prices.py <NEW1> <NEW2>`로 이력·시세를 준비한다. `python scripts/update_market_caps.py --help`로 현재 옵션을 확인하고 대상 시가총액을 검증·반영한다.
3. 종목별 최근 1년 거래일 누락, OHLCV 값의 유효성, 최신 완료 거래일 종가, 시세 시간, 양수 시가총액, 실제 아이콘 로딩을 확인한다. 단순 행 수만으로 통과시키지 않는다.
4. 현재 검수는 240개 이상 일봉과 전체 1년 거래일을 요구한다. 신규 상장 등으로 1년 이력이 존재하지 않는 경우 자동 전환이 차단된다. 데이터로 꾸며 채우거나 검수를 끄지 말고, 상장일에 근거한 명시적 예외와 테스트를 먼저 구현한다. 해당 연도의 휴장일도 갱신한다.
5. 스크리너·카드·검색·상세에서 신규와 기존 종목에 편입/편출 예정일을 표시한다. 공식 지수 수·새 챌린지·Buy/Short는 계속 실제 활성 종목만 허용한다. 기존 보유분 Sell/Cover는 유지한다.

## 4. 배포 전 통과 기준

```sh
npm test
python -m unittest discover -s tests_py
npm run build
python scripts/check_sp100.py
python scripts/audit_market_data.py --no-log
git diff --check
```

- `check_sp100.py`는 읽기 전용이다. 현재 구성 불일치 없음, 편입 데이터 준비 완료, 예상 교체 후 구성 수, 편입·편출 차이만 포함한 미래 계획을 확인한다. 미래 날짜를 운영 동기화에 강제로 넘기지 않는다.
- 전체 데이터 감사의 종료 코드: 0 정상, 1 치명 데이터 문제, 2 미완료. 경고도 내용을 기록한다. 외부 공급자 실패로 비교하지 못한 결과는 정상으로 보고하지 않는다.
- 실제 DB의 종목별 일봉 기간/누락, 아이콘, 시세·시가총액과 준비 상태를 기록한다. 비활성 신규 종목은 활성 종목 전용 전체 감사에 포함되지 않으므로 별도 준비 검수가 필수다.
- 전환 실패 시 전체 상태 유지, 단일 원자적 교체, 재실행 시 추가 변경 없음, 별도 종목·ETF·암호화폐 영향 없음, 사용자 기록 보존을 확인한다.
- `test_rebalance_contract.py`가 UI와 Python의 목록·시각, 백필 기본값, 보존 설정 불일치를 검사한다. 관련 설정의 PR과 main push에서 `Check Index Rebalance Configuration`이 운영 키 없이 자동 실행된다. 나머지 전체 테스트와 데이터 검수는 별도로 수행한다.

## 5. 배포와 효력일 운영

1. 검증한 변경을 커밋·푸시하고 **동일 커밋의** Vercel 배포 성공을 확인한다. GitHub의 최신 시세 수집 및 이력 백필 성공도 확인한다.
2. 실제 사이트에서 목록·검색·상세의 예정일, 신규 1년 차트와 아이콘을 확인한다. 모바일에서도 배지가 잘리지 않는지 확인한다.
3. Cronjob.org가 GitHub 시세 작업을 약 10분마다 호출한다. 코드가 뉴욕 기준 효력일 이후 첫 성공 작업에서 전환한다. 자정 정각 실행을 보장하는 구조는 아니다. 작업 지연·페이지 캐시 시간도 고려한다.
4. 직전 거래일 마감 후 다시 준비 검수한다. 효력일 첫 작업, 장중, 장 마감 후와 다음 날에 활성 상태·구성 수·새 시세·오래된 화면 캐시를 확인한다.
5. 날짜가 지났어도 검수가 실패하면 교체 전체를 보류하며 다음 작업에서 재시도한다. 달력만 보고 완료 처리하지 않는다.

## 6. 장애 복구와 데이터 정리

- GitHub 실패 로그와 `fetch_logs`의 `sp100_sync`를 확인한다. 누락 메타데이터·이력·시세를 대상 티커에 한해 복구한 후 현재 날짜의 정상 동기화를 재실행한다.
- 효력일 이후 이전 코드로 단순 롤백하면 구성을 되돌릴 수 있다. 현재 DB와 공식 구성을 비교해 일관된 수정안을 배포하고, 관련 없는 데이터는 그대로 둔다.
- `cleanup_stocks.sql` 등 과거 전체 삭제 스크립트를 교체에 사용하지 않는다. 정상 교체는 활성 플래그만 바꾸고 종목 행과 사용자 거래 기록은 보존한다.
- 편출 후 30일은 계속 수집·보존한다. 이후 양수 보유 포지션, 관심목록, active/pending 챌린지의 **모든 picks**를 페이지 끝까지 조회해 필요한 종목을 보호한다.
- 참조가 없고 실제 비활성인 종목만 기본 수집에서 제외하고 주간 작업에서 시장 데이터 정리 대상이 된다. 기존 시간별 보존 기한도 적용된다. 명시적 티커 백필은 수동 복구용 예외다.
- 완료된 교체의 자동화는 최종 검수 후 일시중지하고, 다음 교체에 재사용한다.
