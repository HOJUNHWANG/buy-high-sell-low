6. `PAPER_QA_BASE_URL`을 배포 URL로 설정하고 `node tests/e2e/paper-actions.mjs --allow-live-test`를 실행한다. 생성한 QA 신원만 정리됐는지 확인한다.

## DISK IO 관측과 남은 제한

공식 Metrics API를 두 번 읽어 차이를 계산했다. 일괄 복구/브라우저 검사 후 171초 구간의 DB 데이터 디스크(`/data`) busy는 **0.37%**, 약 **8.66 IOPS**였다. 시스템 디스크(`/`)는 busy **22.25%**, 읽기 약 **20.79 MiB/s**였고 스왑 in/out도 약 **646/677 pages/s** 관측됐다. 이는 시스템 메모리/스왑 관련 I/O가 별도로 남아 있다는 증거이며, 앱의 데이터 테이블 쓰기만으로 경고를 설명할 수는 없다. 정확한 원인 귀속에는 추가 인프라 관측이 필요하다.

이 값은 짧은 관측 구간의 장치 사용률이다. Supabase의 일일 `Disk IO % consumed`와 다른 지표이며 경고 해제의 증명이 아니다. 해당 일일 예산 상태는 이번 Metrics API 응답에서 확인하지 못했다. 요금제/컴퓨트/OS 설정은 변경하지 않았다.
