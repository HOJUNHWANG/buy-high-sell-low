## Transition safeguards

- Membership changes use a single bulk upsert transaction, preserving other stock fields and user records. Retries are idempotent; the sync captures one Eastern date for the whole operation.
- Before activating replacements, verify names, sectors, exchange, logo URLs, positive market caps/prices, quotes ingested since the previous session's close, and a trailing year of daily rows with no missing trading sessions. An incomplete replacement blocks the entire switch. Price ingestion continues so the next scheduled run can retry.
- Pending additions and retired equities within a 30-day grace period are protected from inactive-asset cleanup. After the grace period (October 8 for HON; October 21 for the four September removals), collection continues only if a positive position, watchlist entry, or any pick in an active/pending challenge needs the ticker. References are paginated. Active assets remain collectable even if their planned removal is delayed. Weekly cleanup removes unneeded inactive market-data rows; stock identity and user transactions are preserved. Ordinary age-based retention still applies. Default quote, cap, and history collection respect this policy; explicitly requested repair/backfill tickers may override it.
- Buy/Short APIs reject inactive symbols. Sell/Cover remain available; the trade page reads the asset directly instead of depending on active-only search.
- New weekly challenge picks use active assets only. Existing challenge picks and settlement remain intact.
- `python scripts/check_sp100.py` performs a read-only current check and prints the future transition plan without applying it. It is also part of the daily audit workflow.
- If the September 21 check fails, inspect the `sp100_sync` fetch log and GitHub price-run failure. Repair missing metadata/history via the documented seed workflow, refresh quotes with the price workflow, and rerun normal synchronization. Never force an earlier date or run the legacy hard-delete cleanup.
